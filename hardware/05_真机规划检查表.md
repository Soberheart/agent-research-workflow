# 05 真机规划检查表

新项目写真机方案之前，照这张表过一遍。每一项要么写"现有设备够用"，要么写清缺什么、怎么补、谁去确认。

## 1. 先对照设备档案

- [ ] 读完 [设备总览](README.md) 和各份详细档案。
- [ ] 方案里用到的每件设备，在档案里都能找到，并且可信程度是"已核实"。是"口述"或"待确认"的，列进"去实验室要确认的事"。
- [ ] 方案里用到了档案里没有的设备：先去确认有没有，没有就改方案或申请采购，不要默认有。

## 2. 选哪台机器人

- [ ] 按 [06 其他机器人与选型](06_其他机器人.md) §2 选：单臂桌面操作先看 Franka；双臂或遥操作采集先看 Cobot Magic；全身或行走看 G1。
- [ ] 自己实验室的三台够用就不用 UR。要用 UR 时默认 UR5e，并把协商机时写进计划。
- [ ] 双臂任务不用 UR（各只有一台，不在一处）。
- [ ] 选的不是 Franka：先按 [06](06_其他机器人.md) §6 去现场核对一次，把结果交给总览补进档案，再往下写方案。下面第 3 节的具体数字只适用于 Franka，别的机器人按核对结果对照同样的问题。

## 3. 机械臂与夹爪（用 Franka 时的数字）

- [ ] 物体或工作区的尺寸在夹爪开口之内（约 77–80 mm，留余量）。
- [ ] 需要的夹持力不超过 70 N。
- [ ] 负载（物体 + 指尖）不超过 3 kg。
- [ ] 要不要换指尖？要的话：安装部分照搬现成设计，接触部分新设计；排进试配和打印的时间（约一周）。
- [ ] 换指尖后要做的事写进方案：核对零位、重设最低下降高度、更新 Desk 里的末端与负载。
- [ ] 需要的定位精度和现有控制方式对得上（阻抗控制会停在离目标几毫米处，要分段走、读回、补偿）。
- [ ] 需要力信号？只有机械臂自带的外力估计，精度没实测过；要用就先安排一次精度实测。

## 4. 观测

- [ ] 一个可自由摆放的 D435 够不够？不够就写明第二个视角从哪来。
- [ ] 被测物离相机不小于最近测距。
- [ ] 夹爪合拢或手臂遮挡时，要看的部位还看得见吗？看不见就改成"松开后再看"或换视角，并写明这会改变什么。
- [ ] 量测精度要求和相机、标定方法对得上；量真值的工具只有钢尺，要更准就借卡尺或用设计值。

## 5. 计算

- [ ] 真机上有没有在线推理？有的话改成事先在超算上算好，或写明带 GPU 的机器从哪来。
- [ ] 超算上的用量估算（GPU 小时、存储）写出来，和别的项目的占用一起看。

## 6. 时间与人

- [ ] 机时和已有项目错开，问过总览。
- [ ] 单人、每次约 5 小时能做完一天的计划；需要两个人的步骤改掉或另找人。
- [ ] 第一次上真机前留 1–2 天只做检查：通信、限位、标定、相机位置，不采正式数据。
- [ ] 打印件、材料的到货时间排在第一次上真机之前。

## 7. 安全

- [ ] 机械臂每一段运动之前，agent 先把起点、终点、速度、力限写出来，等我回复"确认"再动。
- [ ] 急停在手边；速度和力用保守设置。
- [ ] 软件限位写明：工作空间盒、最低高度、限速。
- [ ] 出错后的恢复流程写明：机械臂停下，我确认现场安全后才恢复。
- [ ] 用 G1 时单独写防摔措施（吊架或保护架、活动范围、谁在旁边）。
- [ ] 用 Cobot Magic 时写明底盘动不动；动的话写活动范围和停车方式。

## 8. 数据

- [ ] 采集格式、判定标准、统计方法先预注册，再采数据。
- [ ] 原始数据写入后不改、不删；视频和图片放在不进 Git 的目录，清单里记 sha256。
- [ ] 进 Ubuntu 前和回 Windows 前的同步步骤写进当天的操作单。

## 9. 交给总览

把上面的结果写成一份"真机方案草稿"，连同"去实验室要确认的事"和"要买的东西"发给总览。总览核对后转成我的待办。
