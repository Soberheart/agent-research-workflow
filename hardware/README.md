## 规划时最容易踩的七条限制

1. **没有本地 GPU。** 真机上要用模型预测，只能事先在超算上算好带过去，或另找带 GPU 的机器。超算不在实验室局域网里，不能做在线推理。
2. **只有一台能自由摆放的相机。** 腕部那台有别的使用者，不能拆，能不能用要问。
3. **手指是定制的**，最大开口约 77–80 mm。换指尖要自己设计、打印、试配，留出几天。
4. **测量手段只有钢尺**，精度约 ±0.5–1 mm。要更准得借卡尺。
5. **只有一台机械臂，几个项目共用。** 真机时间要错开；一个项目换了指尖或改了 Desk 里的末端设置，要告诉另一个项目。
6. **单人操作**，每次约 5 小时。急停要在手边，速度和力用保守设置。
7. **控制链路的实测结果还不全**（实时内核、通信质量、末端坐标换算）。复用这条链路的新项目，细节等这些结果出来再定。

## 没清点过的设备

下面这些**没有核对过有没有**，规划里要用就先去实验室确认，确认后补进本档案：

- 力或力矩传感器、触觉传感器
- 第二台机械臂、移动底座
- 带 GPU 的工作站
- 别的相机（工业相机、事件相机、动捕）
- 卡尺、塞尺

## 怎么维护

- 这份档案只由**项目总览**改。
- 真机 agent 量到新数字、发现型号或状态变了：写进自己 `STATE.md` 的"设备档案更新"一节（写清数值、怎么量的、哪天量的）。总览汇总后更新这里，并改最上面的"最近核对"日期。
- 每条数字都写可信程度和来源日期。估计值和实测值不要混在一起。
- 这个仓库是公开的：**不写**账号名、主机名、IP、本机路径、实验室和学校的名称、未发表的研究内容。
