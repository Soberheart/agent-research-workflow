# 自动运行规则（所有定时运行的 agent 每次开工先读）

- 维护：只由总览写。本文件改了即生效，不用改各定时任务的提示词。

## 1. 开头的快速检查

1. `reports/<自己>/STATE.md` 里记一行 **"上次运行看到的提交：<hash>"**（第一次运行没有，就跳过快速检查、照常工作）。
2. 开工时看自那个提交以来，下面这些路径有没有新提交：
   ```bash
   git log --oneline <上次的提交>..HEAD -- docs/overview reports/需要你处理.md "reports/<自己>/messages" "reports/<自己>/<执行端>"
   git log --oneline <上次的提交>..HEAD --name-only | grep -E "_to_<自己>_"
   ```
   - 本次是被**叫醒**的（提示词后附了任何一段话）：按那段话处理，**不能按快速检查直接结束**。
   - **不进 Git 的本机文件也要看**：STATE.md 里写着在等的文件出现了、或修改时间晚于上次运行，就算有新输入。
3. 没有新提交、没有叫醒附言、在等的本机文件也没变化，并且 STATE.md 的"下一步"全是在等别人：**立即结束，不写任何文件**。
4. 否则照常工作。结束时把当前 HEAD 写进 STATE.md。本机会话（不提交）写入读到的 HEAD 即可。

## 2. 叫醒别人

发出一份**需要对方处理**的新消息后，用 `fire_trigger` 叫醒对方的定时任务，附言：`有新消息：<文件路径>`。

| 对象 | 任务编号 | 在哪跑 | 能否被其他任务叫醒 |
|---|---|---|---|
| <L1> | `<trig_...>` | 云端 | 能 |
| <L2> | `<trig_...>` | 本机 | **不要**（叫醒不带电脑权限，会空跑） |
| 总览巡检 | `<trig_...>` | 本机 | **不要** |

- 本机任务靠自己的定时运行读消息；急事由交互式总览叫醒（它的叫醒带电脑权限）。
- 只在发出**新的、需要对方处理的**消息时叫醒；确认、致谢不叫醒。
- 每次运行对同一个对象最多叫醒一次；不叫醒自己。
- 被叫醒的这一轮如果没有发出新消息，就不叫醒任何人。
- 交互式 agent、远端执行端不在表里：给它们的消息写文件，由用户转达或说固定的话。

## 3. 消息可能还没到

- **云端会话**被叫醒、GitHub 上还没有那份文件：每 2 分钟 `git pull --ff-only` 一次，最多等 25 分钟；仍没有就照常工作，在 STATE.md 记"在等 <路径>"。
- **本机会话**被叫醒、本机还没有那份文件：每 2 分钟检查一次本机文件，最多 25 分钟；不要自己 `git pull`。
- 用循环检查实现，加超时，不要一次长睡。

## 4. 同一个 agent 两轮撞在一起

推送被拒、rebase 冲突：`git rebase --abort`，放弃这一轮未推送的改动，在日志记一笔，结束。下一轮从最新状态重新开始。
