# 05 自动运行

## 1. 两类定时任务

| | 云端定时任务 | 本机定时任务 |
|---|---|---|
| 在哪跑 | Anthropic 云端的隔离环境 | 你电脑上的 Claude 桌面 app |
| 怎么读写仓库 | 每次运行用 add_repo 接入 GitHub 仓库、克隆、提交、推送 | 直接读写本机的仓库副本；**不提交**，交给本机自动同步 |
| 能读本机文件吗 | 不能 | 能（要在桌面 app 的任务设置里授权文件夹） |
| 你关机时 | 照常运行 | 跳过 |
| 设置要点 | **不要**打开"要求使用此计算机" | **要**打开"要求使用此计算机"，并在"本地文件夹"里加上要用的文件夹 |

## 2. 频率

- 执行 agent、总览巡检：白天每 2 小时一次即可，各自错开几分钟（如 :07、:13、:23、:37），避免同一时刻挤在一起。
- 避开整点和半点（很多任务都在整点跑，容易排队）。
- 快速检查让"没事的运行"几乎不花额度，所以频率可以偏高。

## 3. 每次运行的固定流程

写在常驻规则文件 `docs/overview/auto_runs.md`（模板：[templates/repo/auto_runs.md](../templates/repo/auto_runs.md)），每个任务的提示词第一步就是"先读它"。**改这个文件就能改所有任务的行为，不用逐个改提示词**（改定时任务的提示词，本机任务还需要你重新批准）。

1. **快速检查**：STATE.md 里记着"上次运行看到的提交"。开工时看自那以后，和自己有关的路径有没有新提交：
   ```bash
   git log --oneline <上次>..HEAD -- docs/overview reports/需要你处理.md "reports/<自己>/messages" "reports/<自己>/<执行端>"
   git log --oneline <上次>..HEAD --name-only | grep -E "_to_<自己>_"
   ```
   再看 STATE.md 里在等的**本机文件**（不进 Git 的）有没有出现或更新。都没有、手上也没能推进的事 → 立即结束，不写文件。
2. **被叫醒**（提示词后附了一段话）：按那段话处理，不能用快速检查直接结束。
3. 照常工作。
4. 结束：更新日志和 STATE.md（含当前 HEAD），只 `git add` 自己改的文件，`git pull --rebase` 后推送；绝不 `--force`。

## 4. 叫醒别人

agent 发出一条需要对方处理的新消息后，用 `fire_trigger` 叫醒对方的定时任务，附一句"有新消息：<路径>"。规则：

- 只在发出**新的、需要对方处理的**消息时叫醒；确认、致谢不叫醒。
- 每轮对同一个对象最多叫醒一次；不叫醒自己。
- 被叫醒的这一轮没发新消息，就不叫醒任何人（防止互相无限叫醒）。
- **不要叫醒本机任务**：由别的定时任务发起的叫醒，跑起来**拿不到你电脑的权限**，本机任务会空跑。给本机任务的消息写好文件即可，它的定时运行能读到；急的事由交互式总览（你常开的那个对话）叫醒——它的叫醒带电脑权限。
- 交互式 agent 和远端执行端不在叫醒范围内：靠你转达或说固定的话。

## 5. 消息可能比叫醒晚到

云端和本机之间靠 GitHub + 本机每 20 分钟的自动同步衔接，叫醒可能比文件先到：

- 云端任务被叫醒、GitHub 上还没有那份文件：每 2 分钟 `git pull --ff-only` 一次，最多等 25 分钟；仍没有就照常工作，在 STATE.md 记下"在等某文件"。
- 本机任务被叫醒、本机还没有那份文件：每 2 分钟看一次本机文件，最多 25 分钟；不要自己 `git pull`（交给自动同步）。

## 6. 本机自动同步

本机有多个 agent 改文件、但都不提交，由一个计划任务每 20 分钟统一做：提交本地改动 → 拉取（只 rebase 自己的自动提交）→ 推送。脚本见 [scripts/](../scripts/)。

要点：
- 只 rebase 自动同步自己产生的提交（用提交信息里的标记识别），别人的提交一律不改写，**绝不 force push**。
- 推送前检查有没有像凭据的文件，有就停下。
- Windows 计划任务默认"用电池时不启动"，笔记本要显式允许（见 07）。
- 双系统 / 多台电脑：同一时间只让一台机器往仓库推送。切换前手动同步一次，看到推送成功再关机。

## 7. 同一个 agent 两轮撞车

定时运行和叫醒可能让同一个 agent 同时跑两份。推送被拒、rebase 有冲突时：放弃这一轮未推送的改动，在日志记一笔，结束。下一轮会从最新状态重新开始。
