# 04 消息与决策流

## 1. 一件事怎么走完

```
执行 agent 遇到需要决定的问题
   │  写 reports/<自己>/messages/..._to_overview_NN.md（附选项和自己的建议），推送
   ▼
总览（交互对话里，或巡检定时任务）读到
   │  ├─ 已有框架内的例行事项 → 直接写决策记录
   │  └─ 改方向、加减主要实验、超预算、删除 → 写进"需要你处理"，附建议，等你
   ▼
决策记录 docs/overview/decisions/...（README 表格最上面加一行，标"最新"）
   │  叫醒受影响的 agent（规则见 05）
   ▼
执行 agent 读决策 → 照做 → 更新 STATE.md 和日志
   │  需要服务器跑作业：写编号指示 ..._to_<执行端>_NN.md
   ▼
你对执行端说一句固定的话 → 执行端拉取、执行、写回汇报、推送
   ▼
执行 agent 读汇报 → 分析 → 下一步
```

## 2. 决策记录

模板：[templates/repo/decision.md](../templates/repo/decision.md)。必须有：

- **日期**（当天第几份）、**决策人**（总览；用户可否决）、**依据**（哪条消息、哪份旧决策）、**对象**（影响哪些 agent）、**状态**（生效 / 待用户确认）。
- 正文用编号条目，每条一句结论 + 理由。
- 涉及用户答复的，原样引用用户的话。

写完：
1. `docs/overview/README.md` 的"当前有效指令"表**最上面**加一行，标 **最新**，去掉上一份的标记（全表只留一个）；
2. 复制一份到私有工作区；
3. 叫醒受影响的 agent。

**优先级**：用户当前指令 > 最新决策记录 > 任务单 > 交接文档 > 其他历史文档。同一主题以日期最新的为准。

## 3. 总览能直接决定什么

| 直接决定 | 排队等用户 |
|---|---|
| 技术口径（某个指标怎么算、某个边界情况怎么判） | 改变研究方向或贡献主张 |
| 确认报备、认可按已批预算发出的指示 | 增减主要实验 |
| 在已批预注册框架内解释未写明的细节（并在报告里注明） | 超出已批预算 |
| 执行顺序、排期 | 批准新的预注册 |
| 采纳 agent 提出的、不改结论的流程改进 | **任何删除** |

## 4. 给远端执行端的指示

模板：[templates/repo/instruction_to_executor.md](../templates/repo/instruction_to_executor.md)。要点：

- 文件头：日期、发出方、依据、**预计花费**（GPU·小时、仿真次数）、汇报写到哪。
- 每一步写：要运行的**命令**、**正常会看到什么**、**什么情况停下**。
- 删除类指示标题以【删除】开头，单独成条，执行端永远跳过，等用户明确同意。
- 发出后不改；要更正另发新编号。
- 发指示前确认代码已推送，否则执行端拉不到会停下。

用户对执行端只说一句固定的话（写进桌面待办的"习惯"一节）：

> 先 `git pull`，检查 `reports/` 下所有发给执行端、还没有汇报的指示，按日期顺序逐条执行，汇报写回对应的执行端目录并推送。删除类指示跳过，列出来等我确认。

## 5. "需要你处理"

模板：[templates/repo/needs_you.md](../templates/repo/needs_you.md)。

- 只有总览写。各 agent 把需要用户的事写进自己 STATE.md 的"需要用户的事"一节，总览汇总。
- 每条标类型（回答 / 批准 / 决定 / 动手）、来自哪个 agent、做完告诉谁（大多数写"不用转告"，agent 会自己读到）。
- 分"现在 / 习惯 / 以后 / 已完成"四节，最新在上。
- 用户可以直接在条目下面写答复，总览下次读到后转成决策。
- "现在"一节同步到用户的桌面待办。

**写条目时站在用户角度**：给完整路径、给能直接复制的命令或原话、说清"做完之后谁会自动读到"。避免"转告""见某决策"这种需要用户再去翻的说法。
