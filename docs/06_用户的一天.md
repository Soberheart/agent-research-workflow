# 06 用户的一天

## 1. 你只看一个地方

**桌面待办**（`我的待办.md`，模板：[templates/desktop_todo.md](../templates/desktop_todo.md)）。总览会把需要你的事同步过来，分四节：

- **现在**：今天要做的，按先急后缓排；
- **习惯**：反复用到的固定操作（给执行端的那句话、切换系统前先同步……）；
- **以后**：不急的；
- **已完成**：做完打勾，总览会移过去。

可以在条目下面直接写答复（"没看过""按上限"），总览下次读到就会转成决策。

## 2. 对总览说的几句话

| 你说 | 总览做什么 |
|---|---|
| "读一下各 agent 最新的汇报" | 读所有新消息、日志、执行端汇报；汇总，列出等你决定的事和它的建议 |
| "据此决定 XX" | 写决策记录，叫醒相关 agent；需要你转达的，给一句能直接复制的话 |
| "梳理进度和待办" | 更新当天的进度、待办和你的桌面待办 |
| "查看一下待办" | 列出"现在"一节，一项一项带你做 |
| "同步到 GitHub" | 本机已自动同步；急的话告诉你双击哪个脚本 |

其他事情直接用大白话说就行："这个打印件是干嘛的""量什么""帮我画个示意图给负责人"。

## 3. 典型的一天

1. 早上看一眼桌面待办的"现在"（手机上可能已经收到巡检推送）。
2. 回答几个只有你知道的问题，写在待办里或直接告诉总览。
3. 看到"对执行端说那句固定的话"，就去服务器上的执行端会话（终端或手机 Remote Control）说一句。
4. 去实验室 / 线下的事，按待办里的清单做，拍照、量数，回来发给总览。
5. 其余时间不用管：执行 agent 每 2 小时自己醒来，互相叫醒，总览巡检会处理例行决定。
6. 切换电脑或系统前，双击同步脚本，看到推送成功再关机。

## 4. 什么时候需要你介入自动化

- 手机收到"连不上电脑 / 接不上仓库"的通知：截图给总览，大多是设置问题（见 [07](07_踩坑记录.md)）。
- 某个 agent 在 STATE 里写"卡住"：总览会汇总给你。
- 你想换方向、加实验：直接告诉总览，它写决策并通知各 agent。

## 5. 对话太多怎么办

定时任务每次都是新会话，只靠仓库文件接力。所以：
- 已经交给定时任务的 agent，**旧的交互对话可以删**（删之前确认它没在干到一半）；
- 需要和某个 agent 面对面聊时，新开一个对话，第一句："你是 XX agent，先读 `docs/overview/auto_runs.md` 和 `reports/XX/STATE.md`，接着上次的进度，然后……"。聊完它会写回 STATE.md，这个对话用完也可以删。
- 只常留两个对话：项目总览、需要你在场的交互式 agent。
