# 09 机器人项目约定

这套工作流现在专门用来跑我的机器人项目。前面八份文档讲的是通用做法，这一份讲机器人项目特有的部分：通常有哪几条线、真机怎么管、几个项目共用一套设备时怎么不打架。

## 1. 通常的工作线

| 工作线 | 运行方式 | 负责 | 备注 |
|---|---|---|---|
| 项目总览 + 巡检 | 交互 + 本机定时 | 路线、决策、协调、汇总我的待办 | 必须有 |
| 仿真 | 云端定时 | 仿真实验设计、诊断、给执行端写指示 | 计算在超算上，agent 自己不登录 |
| 方法 | 云端定时 | 算法、预注册、正式实验的分析 | 和仿真耦合很重时合并成一个 |
| 真机 | **交互式**，在我笔记本的 Ubuntu 上 | 硬件、标定、采集、真机实验 | 只在我去实验室时开 |
| 超算执行端 | 超算上的 Claude Code | 按编号指示提交作业、贴回原始输出 | 我说固定那句话它才动 |
| 可视化（按需） | 云端定时 | 论文配图、演示视频 | 有结果之后再开；可以中途撤、之后重启 |
| 查新、写论文（按需） | 交互或云端 | 相关工作、论文 | 做完就撤或暂停 |

用到本机数据或本机密钥的线（例如调用大模型 API 的评测）做成本机定时任务。

## 2. 开项目时先读设备档案

- 总览启动时读 [`hardware/`](../hardware/README.md)，把和本项目有关的限制写进第一份决策。
- 真机 agent 的第一张任务单是"按 [真机规划检查表](../hardware/05_真机规划检查表.md) 出真机方案草稿"，在仿真方案定稿之前就做，这样仿真里的假设（指尖尺寸、开口、相机视角、有没有在线推理）一开始就和真机对得上。
- 真机 agent 量到新数字或发现状态变了，写进自己 `STATE.md` 的"设备档案更新"一节。总览汇总后更新工作流仓库的 `hardware/`。

## 3. 仿真和真机的先后

1. **仿真里先把方法做通**，判定标准先预注册。
2. **真机分两段约机时**：
   - 第一段只做准备：通信、限位、标定、相机位置、误差测量、材料选择。不采正式数据。
   - 第二段做正式实验，用第一段实测的误差和参数。
3. 两段之间留出时间，把第一段的实测结果反馈给仿真和方法（误差模型、可行范围）。
4. 真机上要用的模型预测事先在超算上算好。真机方案里不能假设有在线推理。

## 4. 真机安全（写进真机 agent 的提示词）

- 机械臂每一段运动之前，agent 先写出起点、终点、速度、力限，**等我回复"确认"再动**。
- 急停在我手边；速度和力用保守设置。
- 软件限位是第二道保护：工作空间盒、最低高度、限速。路径上任一点无解或超限，动之前就拒绝。
- 出错后机械臂停下。我确认现场安全后才恢复。
- 今天只做检查时，不安装软件、不改系统设置。
- 放宽任何安全参数都不是例行事项，要我点头。

## 5. 真机数据

- 采集格式、判定标准、选例子的规则先写定，再采。看完结果不改采集方式。
- 原始数据写入后不改、不删。
- 表格、元数据、清单进 Git；视频和图片放在不进 Git 的目录，清单里记每个文件的 sha256。
- 每个场次一个目录，带日期和场次号。
- 双系统切换前后都要同步：进 Ubuntu 前在 Windows 上手动同步，回 Windows 前确认已推送。

## 6. 画面和演示

- 仿真画面标明是仿真；真机画面不做生成式 AI 增强。
- 图里的数字只来自已提交的结果文件，可视化 agent 只改显示、不改数据。
- 用作例子的集数按事先写定的规则选，不挑最好看的。
- 配图和视频的分镜先给我看，再渲染。

## 7. 几个项目共用一套设备

现在的情况是：一台机械臂、一台可自由摆放的相机、一个超算账号、一台笔记本，由几个项目共用。

| 共用的东西 | 规矩 |
|---|---|
| 机械臂 | 真机时间错开。排期前问总览现在谁在用。换了指尖、改了 Desk 里的末端或负载设置，在本项目的决策里记一笔，并通知另一个项目的总览 |
| 相机 | 一个项目标定好之后，另一个项目不要挪。要挪先说，挪完各自重新标定 |
| 超算账号 | 每个项目只用自己的目录；指示开头写明"不碰其他项目的目录"；删除类只写路径白名单；根目录不做通配符批量操作；存储用量互相通报 |
| 笔记本 | 每个项目一个仓库、一套同步脚本、各自的日志目录。暂停或恢复同步时说清是哪个项目 |
| 账号用量 | 定时任务多了会碰到用量上限，某一轮会直接失败。不紧急的线把频率调低 |

两个项目的总览之间也用文件传话：一方写一份给对方总览的消息，放进对方仓库约定的位置，或由我转交。涉及共用设备的约定，两边各写一份决策。

## 8. 外部意见和评审

别人对项目提了意见（导师、同行、评审报告）时：

1. 总览先逐条核对事实：对方说的数字、做法，和仓库里的记录对不对得上。自己以前说错的地方一并更正。
2. 分三类回应：要补的分析、要改的措辞、不采纳的（写明理由）。
3. 要补的分析优先用已有数据。**单独写一份补充预注册**，标明"事后追加"，批准冻结后再看结果。原来的判定和结论不改。
4. 要加新实验或超预算的，由我决定。

## 9. 公开和私有

- 研究仓库一律**私有**。
- 这个工作流仓库是公开的，只放做法、模板、脚本和设备档案。不放：未发表的研究路线和结果、账号名、主机名、IP、本机路径、定时任务编号、实验室和学校的名称。
