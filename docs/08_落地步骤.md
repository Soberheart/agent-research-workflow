# 08 落地步骤：新项目从零开始

按顺序做，约半天能搭完。打勾表示完成。

## 第一步：想清楚分工（30 分钟）

- [ ] 写下项目目标、截止时间、有几条工作线（[02 角色设计](02_角色设计.md)）。
- [ ] 每条线：叫什么名字（如 `L1`、`analysis`）、在云端还是本机跑、能改哪些目录。
- [ ] 有没有服务器 / 超算要用？有就加一个远端执行端。
- [ ] 有没有需要你在场的工作（实验、现场调试）？有就加一个交互式 agent。
- [ ] 写下项目红线（密钥、数据删除、公开范围、研究纪律）。

## 第二步：建仓库和文件夹（30 分钟）

- [ ] GitHub 建一个**私有**研究仓库，克隆到本机。
- [ ] 把 [templates/repo/](../templates/repo/) 复制进去，按 [03 目录与文件约定](03_目录与文件约定.md) 放好：
  - `docs/overview/README.md`（填项目简介、规则、红线，"当前有效指令"表先空着）
  - `docs/overview/auto_runs.md`（任务编号表先留空，建好任务后再填）
  - `docs/overview/decisions/`、`docs/overview/task_cards/`
  - `reports/需要你处理.md`
  - 每个 agent：`reports/<agent>/STATE.md`、`reports/<agent>/messages/`
- [ ] `.gitignore` 写好凭据、大数据的排除规则；实验必需的 PDF/图片加例外。
- [ ] 本机建**私有工作区**文件夹（不进 Git）。
- [ ] 桌面建**待办**文件夹，放 [templates/desktop_todo.md](../templates/desktop_todo.md)，以及打开常用文件的快捷方式。

## 第三步：本机自动同步（15 分钟）

- [ ] 按 [scripts/README.md](../scripts/README.md) 配置：Windows 用计划任务，Linux 用 cron，每 20 分钟一次。
- [ ] 手动跑一次，确认推送成功。
- [ ] 笔记本记得允许用电池运行。

## 第四步：启动项目总览（30 分钟）

- [ ] 新开一个 Claude 对话，连接仓库和私有工作区（桌面 app 里授权文件夹，或用 Claude Code 在本机运行）。
- [ ] 第一条消息用 [templates/prompts/overview.md](../templates/prompts/overview.md)，填好项目信息。
- [ ] 让总览复述一遍理解，确认后写第一份决策（项目启动、agent 配置）和第一批任务单。

## 第五步：建定时任务（30 分钟）

- [ ] **云端执行 agent**：用 [cloud_agent.md](../templates/prompts/cloud_agent.md) 作提示词建定时任务，**不要**打开"要求使用此计算机"。
- [ ] **本机执行 agent**：用 [local_agent.md](../templates/prompts/local_agent.md)。在桌面 app 里打开任务设置：打开"要求使用此计算机"，**亲手**在"本地文件夹"里加上它要用的文件夹。
- [ ] **总览巡检**：用 [overview_patrol.md](../templates/prompts/overview_patrol.md)，本机任务，加上研究仓库、私有工作区、桌面待办三个文件夹，打开手机推送。
- [ ] 一个一个创建，频率错开（如每 2 小时，分别在 :07、:13、:23、:37）。
- [ ] 把各任务的编号填进 `auto_runs.md` 的表格。
- [ ] **逐个试跑**：让每个任务在日志里写一行"连接测试：正常"并推送（本机任务不推送，等自动同步），确认都能读写仓库。

## 第六步：远端执行端（可选，30 分钟）

- [ ] 服务器上装 Claude Code，在 tmux 里运行，开 Remote Control。
- [ ] 克隆研究仓库；配置只对这一个仓库有效的推送凭据（deploy key）。
- [ ] 仓库根目录放 [remote_executor_CLAUDE.md](../templates/prompts/remote_executor_CLAUDE.md)（改名为 `CLAUDE.md`）。
- [ ] 把"固定的那句话"写进桌面待办的"习惯"一节。

## 第七步：交互式 agent（需要时）

- [ ] 需要你在场时开对话，第一条消息用 [interactive_agent.md](../templates/prompts/interactive_agent.md)。
- [ ] 它也维护 STATE.md；总览汇总它的"需要用户的事"。

## 跑起来之后

- 每天按 [06 用户的一天](06_用户的一天.md) 操作。
- 发现 agent 太多或太少：告诉总览，它写一份"agent 配置调整"决策，撤销或新增，旧 agent 的进度都在它的 STATE.md 和日志里，不会丢。
- 规则要改：让总览改 `docs/overview/auto_runs.md` 或写新决策，不必改每个任务的提示词。
