# 01 核心理念

七条原则。后面所有的目录、模板、规则，都是为了落实这几条。

## 1. 总览只管路线，不做细活

有一个 Claude 担任**项目总览**：定研究路线、做关键决策、拆任务、审核各 agent 的报告、协调冲突。它**不写实验代码、不跑作业、不写论文正文**，这些交给对应的执行 agent。

为什么：一个对话既想清楚方向又埋头写代码，很快就被细节淹没、上下文爆掉。把"想"和"做"分开，总览的上下文始终留给全局。

## 2. 仓库就是信箱

agent 之间**不通过你转述**，而是在同一个 Git 仓库里读写文件：

- 总览写**决策记录、任务单**（`docs/overview/`）；
- 执行 agent 写**日志、STATE、给总览的消息**（`reports/<agent>/`）；
- 远端执行端写**原始输出汇报**（`reports/<agent>/<执行端>/`）。

你最多只需要说一句"去读某某文件"，很多时候连这句都不用——定时任务会自己去读。

好处：所有沟通都有文字记录、有时间、有版本，不会因为某个对话关掉就丢失。

## 3. 每个 agent 靠文件记住进度

定时任务每次醒来都是全新会话，不记得上一轮。所以每个 agent 维护一份 **`STATE.md`**：做到哪了、下一步、在等谁、需要用户做什么、上次运行看到的提交。

开工先读 STATE.md，结束前更新它。这样：
- 定时任务可以无限次接力；
- 你随时可以删掉旧对话、换新对话、换模型，进度不丢。

## 4. 你只做必须由你做的事

把事情分成四类，只有这四类交给你：

| 类型 | 例子 |
|---|---|
| **回答** | "填表时看过参考答案吗？"——只有你知道 |
| **批准** | 删除数据、超出预算、改变研究方向 |
| **决定** | 两个方案都合理、要看你的偏好 |
| **动手** | 去实验室量尺寸、下单采购、对服务器上的执行端说一句话 |

其余的——技术口径、例行确认、按已批预算发出的指示——总览直接决定，写成决策记录就行。

所有需要你的事汇总在一个文件（`reports/需要你处理.md`），再同步到你桌面的待办。**你不需要去各个对话里翻。**

## 5. 先写下来，再动手

- 研究上：判定标准、统计方法、选择规则**先预注册**，再看数据；看完结果**不调宽**判定线；负结果照实保留。
- 管理上：每个决定都有决策记录（编号、依据、对象、状态），后来的决定覆盖前面的，以日期最新的为准。

这让几十个 agent 回合下来，项目仍然是可审计的。

## 6. 红线写死，所有 agent 共用

在总览的规则文件里写清楚、每个 agent 开工都读：

- 密码、API 密钥、GitHub token **只放环境变量**，不进仓库、日志、报告、对话，也不交给任何 agent。
- 研究数据**不删除**；搬移只能"复制 → 校验 → 软链接"；删除类操作单列，用户点头才执行。
- 公开的仓库里不放未发表的研究路线、创新方案。
- 不改别的 agent 负责的文件；不改总览的目录。

## 7. 自动化要"没事就安静"

定时任务很频繁（每 2 小时），所以每次开头先做**快速检查**：自上次以来有没有和自己相关的新提交、新消息？没有、手上也没能推进的事，就**立即结束、不写任何文件**。

这样既能及时响应，又不会制造一堆"今天无事"的空提交，也省额度。
