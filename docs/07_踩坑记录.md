# 07 踩坑记录

原型项目真实遇到的问题，按类别整理。新项目照着避开就行。

## 定时任务

| 现象 | 原因 | 解决 |
|---|---|---|
| 本机任务每次都说"连不上你的电脑" | 任务创建时没绑定电脑，或绑定了但没挂文件夹 | 在 Claude 桌面 app 里打开任务设置：打开"要求使用此计算机"，在"本地文件夹"里**亲手**加上要用的文件夹（从别处登记的文件夹不算数）。加一个上级文件夹可以一次覆盖多个仓库 |
| 本机任务被别的 agent 叫醒时连不上电脑，定时运行却正常 | 由其他定时任务发起的叫醒不带电脑权限 | 规则里写明"不要叫醒本机任务"；本机任务靠自己的定时运行；急事由交互式总览叫醒 |
| 云端任务突然"没有 add_repo 工具""GitHub 令牌无效""克隆要输用户名" | 任务被误设成"要求使用此计算机"，改到本机跑，用不上云端的 GitHub 连接；之后关掉开关也可能恢复不了 | 云端任务**不要**打开那个开关。已经坏了的，删掉重建（从一个能用 GitHub 的会话里创建，新任务会继承正常的环境） |
| 改提示词时提示"需要在连着那台电脑的对话里批准" | 本机任务的提示词受电脑签名保护 | 在连着那台电脑的对话里改；或者把会变的规则放进仓库里的 `auto_runs.md`，提示词只写"先读它" |
| 同时创建几个任务，只成功一个 | 并发创建失败 | 一个一个创建，创建后列表核对 |
| 等的文件明明到了，agent 却"无事结束" | 文件在被 `.gitignore` 排除的目录里，`git log` 看不到 | 快速检查里加上"STATE.md 里在等的本机文件出现或更新，也算新输入"；叫醒时附带的话一律要处理 |
| 本机任务过一阵就不跑了，任务列表里显示"已停用"、原因是设备不在 | 电脑在任务该运行的时刻关机、睡眠或切到另一个系统，平台会自动暂停这个本机任务，电脑回来后**不会自动恢复** | 交互式总览每次连上电脑时顺手查一下本机任务的状态，被暂停的重新打开；双系统用户切系统前心里有数 |
| 桌面上的文件被"二选一"版本搞乱 | 把要让 agent 读的文件复制到了桌面 | 桌面待办里放**快捷方式**，打开原件；agent 只读原件 |
| 某个定时任务有一轮没干活，任务列表里最近一次运行是"失败"，原因是用量上限 | 定时任务多、频率高，账号用量到了上限，那一轮直接失败 | 总览查看进度时顺手看一眼各任务最近一次运行的状态；不紧急的线把频率调低；失败的那一轮不用补，下一轮会接上 |
| 云端 agent 叫醒另一个 agent 被拒 | 平台有时不允许定时任务之间互相叫醒 | 发消息的一方在 STATE.md 里记"叫醒被拒"；对方下一次定时运行照样会读到；急的由交互式总览补叫 |
| 巡检说找不到桌面待办文件夹 | 用户整理桌面时把文件夹挪走了；本机任务的提示词和授权文件夹里写的还是旧路径 | 桌面待办文件夹定了就不要挪；要挪先告诉总览。改路径要在连着那台电脑的对话里批准一次 |
| 撤掉的 agent 后来又要用 | 一次性的线（可视化、写作）到了后期重新需要 | 总览写一份"重启"决策和新任务单，新建定时任务；提示词里写明"STATE.md 不存在就是重启后第一次运行：先读任务单、决策和交接说明，再新建 STATE.md" |

## 同步

| 现象 | 原因 | 解决 |
|---|---|---|
| 自动同步突然停了，日志里那个时间点根本没有记录 | Windows 计划任务默认"用电池时不启动"，笔记本拔了电源 | 登记任务时加 `-AllowStartIfOnBatteries -DontStopIfGoingOnBatteries` |
| 切到另一个系统后，别的 agent 读不到刚写的决策 | 切换前最后一次自动同步之后的改动还留在本机 | 切换前手动同步，看到推送成功再关机 |
| 工作区干净时自动同步不推送本地已有的提交 | 脚本只在有改动时才推 | 脚本里同时检查"领先远端几个提交" |
| 合并失败后残留 `.git/index.lock` | 没设 git 身份就 merge | 用 `git -c user.name=... -c user.email=...`；清理锁文件前确认没有 git 进程 |
| 远端地址大小写不一致被拒 | 同步脚本按字符串比对远端 URL | 克隆时用和脚本里一模一样的地址 |
| 自动同步连续好几轮都说"另一个同步可能在运行"，几个小时没有提交上 GitHub | 某一轮同步卡在开头（网络、凭据弹窗等），被计划任务的时限强行结束，留下了同步锁文件 | 锁文件里写进程号；同步脚本发现锁的年龄超过时限、或进程已不存在，就当作陈旧锁处理；或由总览把旧锁**改名移开**（不删除）后等下一轮 |
| 两个 agent 同时推送互相覆盖 | 都 force push 或都改了同一文件 | 绝不 force；每个 agent 只改自己的目录；推送被拒就 rebase 一次，还不行就放弃这轮 |
| 想临时停掉自动同步，但手头的对话改不了系统的计划任务 | 连着电脑的对话不一定能运行系统管理命令 | 同步脚本开头加**暂停开关**：日志目录里有 `PAUSE_AUTO_SYNC.txt` 就直接退出。暂停时放这个文件，恢复时把它改名（不删） |
| 同步明明恢复了，巡检和别的 agent 还在说"同步仍暂停" | 总览只记了"已暂停"，没记"已恢复"；别的 agent 照着旧记录说 | 暂停和恢复都在 `需要你处理.md` 顶部各记一行，写清时间；恢复后核对下一轮同步的日志是否正常 |
| 暂停同步期间，本机 agent 写的东西别人看不到 | 本机文件上不了 GitHub | 暂停前告诉用户这个后果；期间的新决策用叫醒附言送给云端 agent，恢复后再补放文件 |
| 一个仓库卡在没做完的 rebase 上好几天，每一轮都推送失败，没人发现 | 同步失败只写进日志，没有人看日志 | 同步脚本失败时在日志目录留一个 `LAST_FAILURE.txt`，成功后改名移开；巡检每次看一眼有没有这个文件，有就写进用户的待办 |
| 用户说"还有个脚本在自动推送"，总览却查到同步已经停了 | 同一台电脑上有两个项目，各有一套同步；停的是这个项目的，在跑的是另一个项目的 | 每个项目一套脚本、一个日志目录、一个暂停开关；暂停和恢复时说清是哪个项目。别的项目的仓库出了问题，告诉用户，不替它修 |

## 协作

| 现象 | 原因 | 解决 |
|---|---|---|
| 执行端拉不到指示里要用的新脚本，停下了 | 发指示时代码还没推送 | 发指示前确认代码已在远端 |
| 总览以为某 agent "没更新" | 它的工作在没合并的分支上 | 检查远端所有分支，不只看 main |
| 用户不知道"转告"要转告什么 | 待办条目写得像给 agent 看的 | 条目站在用户角度写：完整路径、能直接复制的原话、"做完谁会自动读到" |
| 开了太多 agent，管理混乱 | 按任务而不是按工作线分 | 合并强相关的线，一次性任务做完就撤，暂时用不上的先暂停 |
| 跨对话直接发消息不通 | 对话之间不能互相发消息 | 用仓库当信箱 |
| agent 被问到不是它职责的事，自己顺手改了别人的文件 | 边界没写清 | 提示词里列出"只改哪些目录"；要改别人的东西就写消息 |
| 电脑不在线时，总览的新决策传不到本机仓库 | 决策文件只能写进本机仓库，靠本机同步上 GitHub | 先把决策全文写进叫醒云端 agent 的附言里，注明"文件稍后补放，在此之前以附言为准"；电脑连上后再补放文件 |
| 执行端把已经过时的指示也执行了 | 固定那句话是"按日期顺序执行所有没汇报的指示"，旧指示还挂着"待办" | 新指示取代旧指示时，在旧指示顶部改状态为"已被第 N 条取代，不要单独执行"，并在消息索引里同步 |
| 结论的归因说错（例如把效果归给了不是真正起作用的那个部件） | 只盯主检验，没看为区分机制而设的次要组 | 总览转述结果前把各组数字放在一张表里看一遍；发现说错，写一份"措辞更正"决策，判定和数字都不动 |
| 一次性的正式评测跑完却是空目录 | 脚本只在最后一次性写盘，中途异常整轮作废 | 长时间、按条调用 API 的脚本每完成一条就追加写盘；任何异常记为错误继续跑；"只许跑一次"的评测，空结果经总览确认可重跑 |
| 用户每次都问"怎么进执行端""说哪句话" | 操作步骤只在对话里讲过 | 把"怎么进入执行端"的几步和固定那句话一起写进桌面待办的"习惯"一节 |
| 总览对外的总结把方法细节说错了（在哪批样本上校准、某个指标比的是什么） | 凭印象写，没有回到原文 | 给用户、导师或评审的材料里，每个数字和每句做法都回到预注册和报告原文核对一遍；发现以前说错，明确写出更正 |
| 总览说某个效应"方向相反"，被指出推不出来 | 只看了差值，没看拟合斜率是否偏离 1 这类混杂 | 下结论前想一遍"还有什么别的解释"；拿不准就写成"现象"，并安排一项能区分的补充分析 |
| 用户给了一份参考文件，总览连内容结构也照搬了 | "参考这份"指的是版式，不是结构 | 版式跟参考文件，内容结构跟项目里已经确认的框架；拿不准先问一句 |
| 两个项目共用一个超算账号，担心互相删数据 | 没有约定各自的范围 | 每个项目写一份决策：只用自己的目录、指示开头声明不碰对方、删除类只写路径白名单、根目录不做通配符批量操作（见 [09](09_机器人项目约定.md) §7） |

## 服务器上的执行端

| 现象 | 原因 | 解决 |
|---|---|---|
| 执行端会话断网就没了 | 直接在 SSH 里跑 Claude Code | 放进 tmux；开 Remote Control，可以从手机接管 |
| 两台登录节点上的 Claude Code 互相弄崩 | 共享 Home，一边的自动更新删掉了另一边正在用的版本 | 只在一台节点上运行，或关掉自动更新 |
| 执行端推送要凭据 | 服务器上没有 GitHub 写权限 | 给那一个仓库配 deploy key 或细粒度 token，不要用覆盖所有仓库的经典 token，不要在对话里粘贴 |
| 执行端换了一台登录节点在跑 | 登录后落在哪台节点是随机的 | 待办里写明执行端在哪台节点，先 `hostname`，不对就跳过去再 `tmux attach` |
| 执行端"自作主张"重跑失败的作业 | 规则没写死 | 执行端的 CLAUDE.md 写明：只执行指示里写的、失败不重跑、只贴原文不下结论、删除类永远跳过 |
